# Показ работы на занятии

Сценарий показа на 10-15 минут: сервер в Docker на VM, два клиента с разных компьютеров находят
сессию через Steam, играют, выходят, сервер падает и поднимается сам, сессия уничтожается при остановке.

## Что должно быть готово заранее

| Что | Где проверить |
|---|---|
| Собраны билды сервера и клиента | `Builds/LinuxServer/StickmanServer.x86_64`, `Builds/WindowsClient/StickmanClient.exe` |
| Образ сервера загружен на VM, compose-файлы лежат в `~/stickman-pr7/deploy` | `deploy/deploy_to_vm.sh` (Deployment.md, раздел 6.2) |
| В VirtualBox проброшены UDP 7777 и 27015 | `VBoxManage showvminfo adcm-ubuntu2204 --machinereadable \| grep Forwarding` |
| В брандмауэре Windows разрешены входящие UDP 7777 и 27015 | правило «Stickman PR7 UDP» |
| На втором ПК есть папка `Builds/WindowsClient` целиком (вместе с `steam_appid.txt`) и запущен Steam | передать архивом или флешкой |
| На обоих ПК запущен Steam с вошедшим пользователем | значок Steam в трее |

Перед парой стоит один раз пройти весь сценарий с тем же вторым ПК: это единственная часть,
которую нельзя проверить на одном компьютере.

## 1. Сеть

1. На телефоне включить точку доступа, ноутбук подключить к ней по Wi-Fi.
2. На ноутбуке: Параметры → Сеть и Интернет → Мобильный хот-спот → включить. Название и пароль сети
   видны там же.
3. Второй ПК подключить к хот-споту ноутбука.

Университетский Wi-Fi не подходит: в таких сетях обычно включена изоляция клиентов, и компьютеры
не видят друг друга.

## 2. Сервер

1. Закрыть Docker Desktop (значок в трее → Quit). Если он работает, VM загружается в разы дольше.
2. Запустить VM без окна (Git Bash или PowerShell):

   ```bash
   "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" startvm adcm-ubuntu2204 --type headless
   ```

3. Через 30-60 с проверить, что сервер поднялся и опубликовал сессию:

   ```bash
   ssh -i ~/.ssh/adcm_vm -p 2222 user@127.0.0.1 "docker logs stickman-server 2>&1 | grep -E 'READY|опубликована'"
   ```

   Ожидается две строки: `READY: сервер «Stickman Fight PR7» слушает 0.0.0.0:7777/udp ... транспорт
   SteamSocketsTransport` и `сессия опубликована в Steam`. Если пусто, подождать ещё минуту:
   контейнер стартует сам (`restart: unless-stopped`).

   Если контейнер не запущен (`docker ps` его не показывает):

   ```bash
   ssh -i ~/.ssh/adcm_vm -p 2222 user@127.0.0.1 "cd ~/stickman-pr7 && docker compose -f deploy/compose.yaml -f deploy/compose.steam.yaml -f deploy/compose.vbox.yaml up -d --no-build"
   ```

4. Держать открытым окно с логом сервера, его удобно показывать преподавателю:

   ```bash
   ssh -i ~/.ssh/adcm_vm -p 2222 user@127.0.0.1 "docker logs -f --tail 20 stickman-server 2>&1 | grep -E 'Server|Steam|SteamSockets|СЕРВЕР'"
   ```

## 3. Что показывать и что говорить

| Шаг | Действие | Что видно | Требование методички |
|---|---|---|---|
| 1 | Показать `deploy/Dockerfile` и `deploy/compose.yaml` | серверный билд, закреплённые версии, пользователь `game`, `restart: unless-stopped`, порт `7777:7777/udp` | Docker, порты, перезапуск |
| 2 | Лог сервера: строка READY | карта, порт, транспорт `SteamSocketsTransport`, мест 4 | сервер на VM в Docker |
| 3 | Ноутбук: запустить клиент, **«В локальной сети»** | список: название, карта, режим Deathmatch, сборка, игроков 0/4, пинг | поиск с фильтрами, список сессий |
| 4 | **«Подключиться»** | арена, в меню «в игре», транспорт и маршрут «прямое соединение (relay не используется)» | проверка сессии, строка подключения, вход |
| 5 | Второй ПК: то же самое | в лог сервера пишется «игрок 2 подключился, всего игроков: 2/4», персонажи видят друг друга | два клиента из внешней сети |
| 6 | Подвигаться (WASD), рывок (пробел) | движение синхронно на обоих экранах | серверная авторитетность, репликация ПР5 |
| 7 | Второй ПК: **«Выйти из сессии»**, затем снова «В локальной сети» и «Подключиться» | выход и повторный вход без перезапуска игры | выход, повторный вход |
| 8 | Аварийное завершение сервера (команда ниже) | у клиентов через 15-20 с «сервер перестал отвечать», контейнер поднялся сам, сессия опубликована заново | перезапуск после аварии, обработка ошибок |
| 9 | Клиенты: «Назад к поиску», снова найти и войти | вход в новую сессию | восстановление |
| 10 | Штатная остановка (команда ниже) | у клиентов сразу «сервер завершил работу», в логе «сессия снята с публикации и уничтожена» | уничтожение сессии, корректная остановка |
| 11 | Клиент: «В локальной сети» | «сессий не найдено» | сессия действительно удалена |

Команды для шагов 8 и 10 (в отдельном окне):

```bash
# 8. Падение процесса сервера
ssh -i ~/.ssh/adcm_vm -p 2222 user@127.0.0.1 "docker exec stickman-server sh -c 'kill -9 \$(pgrep -f StickmanServer.x86_64)'; sleep 15; docker inspect -f 'RestartCount={{.RestartCount}}' stickman-server"

# 10. Штатная остановка
ssh -i ~/.ssh/adcm_vm -p 2222 user@127.0.0.1 "cd ~/stickman-pr7 && docker compose -f deploy/compose.yaml -f deploy/compose.steam.yaml -f deploy/compose.vbox.yaml stop && docker inspect -f 'ExitCode={{.State.ExitCode}}' stickman-server"
```

Запустить сервер снова после шага 10:

```bash
ssh -i ~/.ssh/adcm_vm -p 2222 user@127.0.0.1 "cd ~/stickman-pr7 && docker compose -f deploy/compose.yaml -f deploy/compose.steam.yaml -f deploy/compose.vbox.yaml up -d --no-build"
```

## 4. Вопросы, которые могут задать

| Вопрос | Ответ |
|---|---|
| Почему поиск «в локальной сети», а не через интернет? | У стенда нет публичного IP. Мастер-сервер Steam нашу сессию возвращает, но опрос сервера по внешнему адресу из той же сети роутер не пропускает (NAT hairpin). Интерфейс тот же, `ISteamMatchmakingServers`, строку подключения выдаёт Steam. На VM с публичным IP работает поиск через интернет без изменений кода. Подробно: Deployment.md 6.2 |
| Где здесь relay? | Соединение Steam Sockets устанавливается по IP-адресу, оно прямое; маршрут проверяется и выводится в меню. Relay экспериментально не подтверждён: для него нужно подключение по SteamID, а учебный App ID 480 этого не даёт |
| Где сервер проверяет действия игрока? | `PredictedMovement.ServerApply` и `MovementSim.ValidateDash`: кулдаун, земля, длина вектора ввода. Доказательство: сценарий 02 в Test_Evidence.md, 16 отклонённых рывков |
| Почему ufw не защищает игровой порт? | Docker публикует порты своими правилами iptables в обход ufw. Граница доступа это правила облака, на стенде брандмауэр Windows и проброс VirtualBox |
| Что за `compose.vbox.yaml`? | VirtualBox на Windows с Hyper-V работает через Hyper-V, и часы на ядрах VM расходятся; Steam Sockets от этого сбоит. Сервер привязан к одному ядру: 74 ошибки времени без привязки, 0 с ней |
| Что за `S_API FAIL` и `flock ... errno = 13` в логе? | Служебные сообщения Steam, разобраны в Deployment.md, раздел 8 |

## 5. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| «Сессий не найдено» на втором ПК | проверить, что он подключён к хот-споту ноутбука, а не к другой сети; что на ноутбуке есть правило брандмауэра «Stickman PR7 UDP»; что в логе сервера есть «опубликована» |
| «Steam недоступен» | запустить Steam и войти, перезапустить клиент |
| Сессия найдена, но «не ответил за 10 с» | нажать «Назад к поиску» и подключиться ещё раз; если повторяется, перезапустить контейнер командой «Запустить сервер снова» |
| VM не отвечает по SSH дольше 2 минут | закрыть Docker Desktop, выключить VM (`VBoxManage controlvm adcm-ubuntu2204 poweroff`) и запустить снова |
| Ничего не помогает | показать локальный стенд: включить Docker Desktop и запустить `docker compose -f deploy/compose.yaml -f deploy/compose.steam.yaml up -d --build` на ноутбуке, клиенты так же ищут «В локальной сети» |

После занятия выключить VM:

```bash
"C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" controlvm adcm-ubuntu2204 acpipowerbutton
```
