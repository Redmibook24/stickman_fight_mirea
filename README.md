# Stickman Fight — сетевой файтинг на UDP

**Учебный проект** для погружения в клиент-серверное взаимодействие по протоколу UDP.  
Цель - создать игру, где два или более стикменов сражаются на арене, а все действия передаются через сеть.

---

## Игровая механика (минималистично)

- Каждый игрок управляет палочным человечком.
- Управление: **влево/вправо**, **прыжок**, **удар**.
- Удар наносит **15 урона**, если противник находится в радиусе атаки.
- У каждого **100 HP**. При 0 HP — игрок выбывает (или игра перезапускается).
- Арена — плоская платформа (без гравитации в сложной физике, только прыжок по параболе).

---

## Архитектура сети

### Топология: **выделенный сервер**


- **Сервер** — это «истинный» мир. Он хранит позиции, HP, состояния всех игроков и обрабатывает логику (попадания, коллизии с границами).
- **Клиенты** — только отправляют команды (нажатия клавиш) и получают от сервера полное состояние игры для отрисовки.
- Такой подход упрощает синхронизацию и защиту от читов (сервер всё решает).

### Обмен данными

- Клиент → Сервер: **команды** (движение, прыжок, атака).
- Сервер → Клиент: **состояние мира** (все объекты с их координатами и HP) — рассылается **50 раз в секунду** (каждые 20 мс).

---

## 📡 Протокол передачи (поверх UDP)

Используем **бинарный формат** для компактности и скорости.

### 1. Сообщения от клиента → сервер (размер 3–18 байт)

Заголовок (общий):

| Байт | Поле | Описание |
|------|------|----------|
| 0    | `cmd` | Тип команды (1 байт) |
| 1    | `seq` | Номер пакета (для обнаружения потерь) |

Типы команд (`cmd`):

| Код | Команда | Доп. данные |
|-----|---------|-------------|
| 0x01 | Движение | 1 байт: 0=стоп, 1=влево, 2=вправо |
| 0x02 | Прыжок | нет |
| 0x03 | Атака  | нет |
| 0x04 | Подключение | имя игрока (строка до 16 байт, завершается `\0`) |

> Пример пакета для движения вправо: `[0x01, 0x42, 0x02]` (где `0x42` — номер пакета).

### 2. Сообщения от сервера → клиенту (состояние мира)

Размер: **4 + N * 6 байт**, где N — число игроков.

| Байты | Поле | Описание |
|-------|------|----------|
| 0–3   | `tick` | номер кадра (uint32) |
| 4     | `count` | количество игроков (uint8) |

Далее для **каждого игрока** (повторяется `count` раз):

| Байт | Поле | Описание |
|------|------|----------|
| 0    | `id`  | ID игрока (uint8) |
| 1    | `x`   | позиция X (uint8, 0–255, масштабируем под арену) |
| 2    | `y`   | позиция Y (uint8, 0–255) |
| 3    | `hp`  | здоровье (0–100) |
| 4    | `flags` | бит 0: атакует, бит 1: в прыжке |
| 5    | `dir` | направление (0=влево, 1=вправо) |

> Все числа целые беззнаковые — экономим байты. На клиенте их можно интерполировать для плавности.

## ⚙️ Обработка потерь и задержек (базовая)

- Команды от клиента отправляются **сразу** при нажатии клавиши (без ожидания подтверждения).
- Сервер принимает команды и **мгновенно применяет** их к состоянию игры в следующем такте.
- Если пакет потерян — сервер просто не получит команду, и игрок в этот кадр не сдвинется. Это приемлемо для прототипа.
- Для сглаживания движения клиент хранит последние 2–3 состояния от сервера и делает **линейную интерполяцию** между ними.

---

## 🛠️ Технологии и структура проекта

- **Язык**: C++17 (можно Python, но тогда сложнее с производительностью).
- **Сеть**: стандартные BSD-сокеты (UDP).
- **Сборка**: CMake.
- **Графика** (опционально): можно сделать консольный вывод или использовать SFML/SDL2 для отрисовки стикменов.
