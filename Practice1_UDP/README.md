# Практическая работа №1 — UDP-сервер и UDP-клиент

Консольная реализация сетевого «рукопожатия» и двух базовых механик игры
[«Битва жердяев»](https://github.com/Redmibook24/stickman_fight_mirea): **движение** (`MOVEMENT`)
и **выстрел** (`SHOOT`).

* Язык: **C# / .NET 9**, сокеты — `System.Net.Sockets.UdpClient` (обёртка над Berkeley Sockets).
* Топология: **dedicated server** — клиент только просит, авторитетное состояние считает сервер.
* Протокол: собственный **бинарный** формат, заголовок 12 байт + полезная нагрузка, CRC32.

## Сборка

Нужен [.NET SDK 9.0](https://dotnet.microsoft.com/download) (проверялось на 9.0.203, Windows 11).

```bash
dotnet build
```

## Запуск

В первом окне терминала — сервер:

```bash
dotnet run --project src/StickmanFight.Server -- --port 9050
```

Во втором — клиент (можно запустить несколько, сервер различает игроков по адресу и порту):

```bash
dotnet run --project src/StickmanFight.Client -- --host 127.0.0.1 --port 9050 --name Жердяй --interval 1000
```

### Аргументы

| Программа | Аргумент     | По умолчанию  | Назначение                                    |
|-----------|--------------|---------------|-----------------------------------------------|
| сервер    | `--port`     | `9050`        | UDP-порт для приёма                           |
| сервер    | `--log`      | `logs`        | каталог для файла лога                        |
| клиент    | `--host`     | `127.0.0.1`   | адрес сервера                                 |
| клиент    | `--port`     | `9050`        | порт сервера                                  |
| клиент    | `--name`     | `Жердяй-NNN`  | имя игрока, передаётся в пакете `CONNECT`      |
| клиент    | `--interval` | `1000`        | периодичность отправки команд, мс             |
| клиент    | `--count`    | `0`           | сколько команд отправить (`0` — бесконечно)   |

Выход из обеих программ — `Ctrl+C` (клиент перед выходом шлёт `DISCONNECT`).

## Что происходит при запуске

1. Клиент отправляет `CONNECT` с именем игрока и ждёт `CONNECT_ACK` — это рукопожатие.
   Если ответа нет, `CONNECT` повторяется, всего до пяти попыток с таймаутом в секунду.
2. Сервер заводит игрока (id, стартовая позиция, HP = 100, патроны = 30) и отвечает его состоянием.
3. Раз в секунду клиент по очереди шлёт `MOVEMENT` (смещение по трём осям) и `SHOOT`
   (id оружия + направление). Каждый пакет получает свой порядковый номер.
4. Сервер проверяет пакет, применяет команду к состоянию игрока и отвечает:
   * на `MOVEMENT` — `STATE_UPDATE` с новой позицией;
   * на `SHOOT` — `SHOOT_RESULT` (попадание/промах, урон, остаток патронов).
   В ответе дублируется номер обработанной команды (`AckSequence`) — это и есть подтверждение.
5. Все полученные команды сервер пишет в консоль и в `logs/server-ГГГГ-ММ-ДД.log`.

## Проверки на стороне сервера

Сервер авторитетен и не доверяет клиенту:

* **CRC32** — повреждённая датаграмма отбрасывается с записью в лог;
* **версия протокола и `PayloadSize`** — пакет неверной длины или чужой версии отвергается;
* **порядковые номера** — повторный или «опоздавший» пакет (`seq` не больше последнего принятого)
  не применяется к состоянию, клиенту возвращается текущее состояние;
* **шаг перемещения** — смещение больше 5 м за команду обрезается, позиция ограничена ареной ±50 м
  (клиент каждую четвёртую команду `MOVEMENT` намеренно шлёт смещение 42 м — видно, как сервер его режет);
* **команды без рукопожатия** — в ответ уходит пакет `ERROR`;
* **выстрелы** — учитывается кулдаун 200 мс и остаток патронов.

## Что дальше (следующие практики)

В `PacketType` зарезервированы коды 12–16 под остальные механики «Битвы жердяев»
(ближний бой, рывок, захват, щит, подбор предметов), а в заголовке есть поле `Reserved`
для расширения без смены версии протокола.
