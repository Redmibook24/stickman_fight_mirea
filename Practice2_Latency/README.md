# Практическая работа №2 — телеметрия UDP: RTT, SRTT, джиттер, потери

Консольные UDP-сервер и клиент с пакетами `PING`/`PONG` и подсистемой измерения задержек
для игры [«Битва жердяев»](../README.md).

* Язык: **C# / .NET 9**, сокеты — `System.Net.Sockets.UdpClient`.
* Сетевой ввод, сериализация и расчёт метрик разнесены по отдельным модулям.
* Тесты: **xUnit**, 56 тестов (сериализация, статистика, ошибочные пакеты, эмулятор сети).

## Структура

```
Practice2_Latency/
├── protocol/    сериализация PING/PONG, заголовок, проверки входных данных
├── telemetry/   монотонные часы, классификация ответов, RTT/SRTT/джиттер/потери, журнал CSV
├── transport/   UDP-сокет и эмулятор сети (задержка, джиттер, потери, дубликаты)
├── server/      UDP-сервер: отвечает PONG, отбрасывает некорректные датаграммы
├── client/      UDP-клиент: шлёт PING по расписанию, собирает замеры
├── tests/       модульные тесты xUnit
├── tools/       run_experiments.ps1 (прогон сценариев), plot_latency.py (графики)
└── docs/        Protocol_Specification.md, Experiment_Config.md,
                 Latency_Report.md, latency_samples.csv, graphs/
```

Зависимости направлены в одну сторону: `server`/`client` → `protocol`, `telemetry`, `transport`.
Модуль `telemetry` не знает ни про сокеты, ни про формат пакетов — он принимает номера
пакетов и отметки времени, поэтому проверяется тестами без сети.

## Сборка и тесты

```bash
dotnet build
```

```bash
dotnet test
```

## Запуск

Окно 1 — сервер:

```bash
dotnet run --project server -- --port 9060
```

Окно 2 — клиент:

```bash
dotnet run --project client -- --host 127.0.0.1 --port 9060 --experiment baseline --count 50 --interval 300
```

Клиент печатает каждый замер и сводку, а строки замеров дописывает в `docs/latency_samples.csv`.

### Аргументы

| Программа | Аргумент       | По умолчанию              | Назначение                                        |
|-----------|----------------|---------------------------|---------------------------------------------------|
| сервер    | `--port`       | `9060`                    | UDP-порт                                          |
| сервер    | `--emulate`    | нет                       | эмуляция сети: `delay=100,jitter=50,loss=5,duplicate=10` |
| сервер    | `--seed`       | `20250920`                | зерно генератора эмулятора                        |
| сервер    | `--quiet`      | —                         | не печатать каждый принятый PING                  |
| клиент    | `--host`       | `127.0.0.1`               | адрес сервера                                     |
| клиент    | `--port`       | `9060`                    | порт сервера                                      |
| клиент    | `--experiment` | `baseline`                | идентификатор сценария в журнале                  |
| клиент    | `--count`      | `50`                      | сколько PING отправить                            |
| клиент    | `--interval`   | `300`                     | периодичность отправки, мс                        |
| клиент    | `--timeout`    | `1000`                    | через сколько ответ считается потерянным, мс      |
| клиент    | `--warmup`     | `2`                       | прогревочные PING вне журнала                     |
| клиент    | `--csv`        | `docs/latency_samples.csv`| файл журнала измерений                            |

## Эксперимент

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_experiments.ps1
python tools/plot_latency.py
```

Первая команда прогоняет шесть сценариев (`baseline`, `delay_50`, `delay_100`, `jitter`,
`loss_5`, `combined`) по 50 PING и перезаписывает `docs/latency_samples.csv`.
Вторая строит графики в `docs/graphs/` и печатает сводную таблицу.
